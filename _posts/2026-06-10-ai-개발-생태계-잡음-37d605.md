요 며칠 AI 개발 현장 소식을 훑다 보니, 좋은 뉴스보다 잡음이 더 눈에 띄더라. 애플이 EU에선 Siri 신기능 출시를 일단 접었고, 마이크로소프트가 풀어둔 오픈소스 도구가 해킹당해 개발자들 비밀번호가 털렸고, 거기에 "AI 록스타 개발자"가 떠난 자리를 누군가 수습하고 있다는 글까지. 셋 다 결이 다른 이야기인데, 묶어놓고 보니 묘하게 같은 방향을 가리키는 것 같았다.

애플 건부터. EU에는 DMA(디지털시장법)라는 게 있다 — 큰 플랫폼 기업한테 "너희 생태계 좀 열어라, 외부랑 데이터 주고받게 해라" 강제하는 규제다. 애플은 새 Siri를 EU에서도 똑같이 굴리려면 이 법 때문에 사용자 데이터를 외부에 노출해야 할 수 있다고 보고, 면제를 요청했다가 거절당하자 그냥 역내 출시를 보류했다. 솔직히 나는 이게 "보안 때문"이라는 명분과 "규제가 싫다"는 속내가 반반 섞인 결정으로 보인다. 어느 쪽이든, 같은 AI 기능이 사는 동네에 따라 켜지고 꺼진다는 건 앞으로 자주 볼 풍경일 거다.



두 번째가 더 무섭다. 마이크로소프트가 공개한 오픈소스 개발 도구가 변조돼서, 그걸 받아 쓴 AI 개발자들의 자격증명(비밀번호·토큰)을 빼가도록 만들어졌다는 거다. 이게 좀 웃긴 게 — 우리가 매일 `pip install`, `npm install` 한 줄로 끌어다 쓰는 그 신뢰가 정확히 공격 표면이 된다. 요즘 AI 프로젝트는 의존성 트리가 수백 개씩 달리는데, 그 중 하나만 오염돼도 내 API 키가 새는 거다. 체감상 모델 성능 튜닝보다 이쪽 위생 관리가 훨씬 더 급한 일인데, 다들 재밌는 데(모델)만 본다.

```bash
pip install --require-hashes -r requirements.txt
```

세 번째, "록스타 개발자 뒷정리". 빠르게 치고 빠지는 화려한 개발자가 코드를 던져놓고 가면, 남은 사람이 그 빚을 갚는다는 이야긴데 — 요즘은 여기에 AI 코드 생성이 끼면서 부피가 확 커졌다. LLM이 그럴듯한 코드를 빠르게 뽑아주니 일단 굴러는 가는데, 왜 그렇게 짰는지 아무도 모르는 코드가 쌓인다. 내 환경에서도 비슷한 일이 있었다. 처음엔 빠른 줄 알았는데, 6개월 뒤 그 코드 읽는 데 든 시간이 처음 아낀 시간을 다 까먹더라.

세 사건을 줄 세워 보면 규제, 보안, 품질. 전부 AI가 빨리 퍼지는 속도를 현실의 다른 시스템들이 못 따라가서 생기는 마찰이다. 빠른 게 나쁘다는 얘기가 아니라, 빠를수록 뒤를 봐주는 사람의 몫이 커진다는 거지. 이 마찰이 시간이 지나며 줄어들지, 아니면 그냥 새로운 표준이 될지는 나도 좀 더 지켜봐야 할 것 같다.
