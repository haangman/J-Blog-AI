마인크래프트 2b2t 서버 전체를 통째로 다운받아 보존한 프로젝트와, 허깅페이스 모델 파일을 좀 덜 짜증나게 받게 해주는 Tampermonkey 스크립트가 같은 주에 굴러다녀서 묶어서 봤다. 둘 다 "왜 큰 파일 다루는 게 이렇게 손이 많이 가지" 라는 같은 짜증에서 출발한 도구다.

먼저 2b2t. 모르는 사람을 위해 한 줄로 풀면, 2b2t 는 마인크래프트에서 13년 넘게 운영 중인 무규칙(anarchy) 서버다. 규칙도 없고 운영자 개입도 거의 없어서 사실상 디지털 폐허 박물관 같은 곳. 누군가 이 서버의 월드 데이터를 1,024,000 × 1,024,000 블록 영역까지 통째로 다운로드하고, 그 안에서 발견된 구조물·기지·낙서들을 기록으로 남긴 프로젝트가 HN 에 올라왔다.

체감이 잘 안 잡힐 텐데, 1024000 블록 한 변이면 마인크래프트 1 블록을 1m 로 잡았을 때 한 변 1024 km 의 정사각형 영역이다. 한반도 남북 길이가 1100 km 정도니까 그 비슷한 면적을 통째로 떠 와서 디스크에 박아둔 셈. 이게 좀 웃긴 게, 마인크래프트 월드 데이터는 청크 단위로 압축돼 있어서 사람이 안 가본 좌표는 파일도 안 만들어진다 — 그러니까 실제로 보존된 건 "사람이 다녀간 흔적이 있는 곳" 들이고, 그게 13년치 누적된 거다.

내가 이 프로젝트를 흥미롭게 본 건 archival 관점에서다. AI 학습 데이터 얘기할 때 "interaction trace" 라는 말이 자주 나오는데, 게임 서버 월드 덤프는 그 극단적인 예다. 의도된 텍스트가 아니라 "행동의 흔적" 그 자체가 데이터인 거. 이걸 LLM 학습에 직접 갖다 쓰진 못해도, 멀티에이전트 환경에서 사람 행동을 모사해야 할 때 이런 식의 "버려진 공간" 데이터셋이 점점 가치 있어질 것 같다. 내가 잘못 보고 있을 수도 있는데.

이어서 HF 다운로더 얘기. r/LocalLLaMA 에 올라온 Tampermonkey 스크립트인데 — Tampermonkey 는 브라우저에 자바스크립트를 끼워 넣어 특정 사이트의 동작을 바꿔주는 확장이다 — 허깅페이스 모델 페이지에 들어가면 파일 목록 아래에 다운로드 표를 자동으로 띄워준다. 그 표에서 직접 wget/curl 명령어를 뽑아 쓰게.

이게 왜 필요하냐면, 사실은 huggingface-cli 가 이미 있다. 근데 70B 클래스 모델 파일 일부만 받고 싶다거나, 회사 방화벽 뒤에서 프록시 통해서 받아야 한다거나, 같은 모델을 여러 서버에 분산으로 받고 싶을 때, CLI 가 묶어 처리해주는 게 오히려 거추장스러울 때가 있다. 솔직히 나도 양자화된 GGUF 파일 하나만 골라서 받고 싶을 때 web UI 에서 마우스로 클릭하는 게 제일 빠르더라.

```bash
wget -c "https://huggingface.co/.../resolve/main/model-Q4_K_M.gguf" \
  --header="Authorization: Bearer $HF_TOKEN"
```

이런 류의 도구는 huggingface_hub 라이브러리가 모든 use case 를 정조준 못 하는 틈에서 자란다. 공식 SDK 는 일반화를 위해 설계되고, 커뮤니티 스크립트는 "내 환경에서 짜증나는 그 한 가지" 를 풀기 위해 설계된다. 둘이 같은 문제처럼 보여도 결이 다르다.

두 프로젝트를 묶어서 보면 패턴이 비슷하다. 공식 도구는 평균적인 사용자를 가정하고 만들어지고, 비공식 커뮤니티 도구는 평균 바깥에 있는 사용자 — 엄청 큰 걸 받고 싶거나, 엄청 옛날 것까지 보존하고 싶거나, 엄청 세밀하게 고르고 싶거나 — 그쪽을 메운다. AI 쪽도 점점 이런 양상이 짙어지는 것 같다. vLLM, llama.cpp, exllama 같은 추론 엔진들 다 그렇게 시작했고.

체감상 LLM 생태계에서 "공식 CLI 가 못 해주는 한 가지" 를 메우는 작은 스크립트가 한 달에 두세 개씩 r/LocalLLaMA 에 올라온다. 대부분 1주일 뒤에 잊혀지지만, 가끔 그중 하나가 결국 huggingface_hub 본체에 머지되기도 한다. 이게 어느 쪽 방향으로 굴러갈지는 좀 더 봐야 할 것 같다.
