요즘 해커뉴스 첫 화면에 프로그래밍 언어 타입 시스템을 다룬 글이 두 개나 나란히 떠 있더라. 하나는 "C 배열 타입은 좀 이상하다"는 글이고, 다른 하나는 파이썬의 opaque 타입 — 속을 들여다보지 못하게 막아둔 타입 — 얘기. 결은 다른데 같이 읽으니까 언어마다 타입을 대하는 태도가 이렇게나 다르구나 싶어서 좀 재밌었다.

먼저 C 쪽부터. 배열이 이상하다는 건 C 좀 만져본 사람이면 한 번쯤 데여본 얘기다. 핵심은 배열이 자꾸 포인터로 "붕괴(decay)"한다는 거. 배열을 함수에 넘기는 순간, 배열이라는 정보가 슬그머니 포인터로 바뀌어버린다.

```c
void f(int arr[10]) {
    // 여기서 arr 은 int* 다.
    // sizeof(arr) 은 배열 크기가 아니라 포인터 크기(보통 8)만 돌려준다.
}
```

겉보기엔 `int arr[10]` 이라고 길이까지 친절하게 적어놨는데, 컴파일러는 그 10을 그냥 무시한다. 함수 안으로 들어온 arr 은 길이를 잃어버린 맨 포인터일 뿐이거든. 그래서 C에선 배열 길이를 늘 별도 인자로 들고 다녀야 하는 거고.

왜 이렇게 만들었나 하면, C가 배열을 1급 시민으로 안 봐서다. 통째로 값 복사해서 넘기는 동작을 일부러 막아둔 설계라고 보면 된다.

```mermaid
graph LR
  A["int arr[10]<br/>길이 정보 있음"] -->|함수 인자로 전달| B["int* 포인터<br/>길이 소실"]
  B --> C["sizeof = 포인터 크기뿐"]
```

진짜 웃긴 건 `a[i]` 가 사실 `*(a + i)` 의 줄임말이라는 점. 그래서 `a[i]` 랑 `i[a]` 가 완전히 똑같이 동작한다. `3[arr]` 라고 거꾸로 써도 컴파일이 멀쩡히 된다는 소리지. 실무에서 쓸 일이야 없지만, 배열이라는 게 C 안에서 얼마나 얇은 개념인지 보여주는 농담 같은 사례더라.

반대편 파이썬 opaque 타입은 정반대 고민에서 나온 것 같다. 파이썬은 애초에 동적 타입 언어라 변수에 뭐가 들었는지 실행 전엔 잘 모르잖아. 근데 거기에 타입 힌트를 얹으면서, 같은 자료형이라도 의미가 다르면 섞지 못하게 구분 짓고 싶어진 거지. opaque 타입을 한 줄로 풀면 "이건 int 인데, 평범한 int 로는 못 쓰게 막아둔 int" 정도 되겠다.

`typing.NewType` 이 대표적인 도구다.

```python
from typing import NewType

UserId = NewType("UserId", int)
TokenId = NewType("TokenId", int)

uid = UserId(42)
```

런타임에 uid 는 그냥 정수 42다. NewType 이 뭘 감싸는 객체를 새로 만드는 게 아니라, mypy 같은 타입 체커한테만 "얘는 UserId 니까 평범한 int 랑 섞지 마"라고 귀띔하는 거거든. 그래서 UserId 를 받는 함수에 TokenId 를 집어넣으면 체커가 빨간 줄을 그어준다. 정작 실행은 아무 문제 없이 되는데도 말이지.

이게 나한테 왜 와닿냐면 — LLM 다루다 보면 정수 id 가 사방에 굴러다닌다. user id, session id, 토큰 id, 문서 청크 인덱스... 죄다 그냥 int 다 보니 인자 순서 한 번 헷갈리면 엉뚱한 데이터를 조회하게 되더라. 예전에 이걸로 반나절을 디버깅에 날린 적 있다. opaque 타입으로 묶어두면 그런 실수를 코드 돌리기 전에 걸러주니까, 한 번 데인 뒤로는 꽤 챙겨 쓰는 편.

두 글을 포개놓고 보면 방향이 정반대라 흥미롭다. C는 성능이랑 컴파일러 편의를 위해 배열을 일부러 얇게 다뤄서 개발자가 정보를 잃게 만든다. 파이썬은 느슨한 동적 타입 위에 일부러 단단한 구분을 덧칠해서 개발자가 실수를 덜 하도록 거들어준다. 한쪽은 깎아내고 한쪽은 덧대는 셈이지.

물론 파이썬 opaque 타입도 만능은 아니다. mypy 나 pyright 를 안 돌리면 NewType 은 그냥 장식일 뿐이고, 런타임이 보장해주는 건 사실상 하나도 없다. C의 배열 decay 야 익숙해지면 그러려니 하게 되고. 결국 타입 시스템이란 건 그 언어가 "뭘 믿고 뭘 의심하느냐"의 성격 같은 거 아닐까. 정수 하나를 두고도 이렇게 다르게 대하는 걸 보면 더 그렇고.

요새 Rust처럼 배열 길이까지 타입에 박아넣는 언어를 만지다가 C랑 파이썬을 다시 보니 더 그런 생각이 들더라. 이 간극이 앞으로 좁혀질지, 아니면 그냥 각자의 철학으로 남을지는 좀 더 지켜봐야 할 것 같다.
